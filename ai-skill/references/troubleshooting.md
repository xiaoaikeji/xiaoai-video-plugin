# 播放问题排查

按顺序排查，找到可复现的最小失败点后停止，不要同时改动多个无关配置。

## 1. token 无效或过期

1. 确认客户小程序 APPID 已替换到项目自己的配置中。
2. 确认插件 provider 仍为 `wxd4709e80d42cb833`，没有误改成客户 APPID。
3. 确认 token 已替换、没有多余空格、使用了当前小程序对应的授权值。
4. 配置无误仍提示无效，或明确提示过期时，向插件服务方获取新 token。

不要在排错输出、截图、日志或提交中暴露完整 token。官网不同页面出现过不一致的微信号，联系时优先通过最新官网或“联系咨询”页核对当前方式：https://weixin.xiaoaikeji.net/guide/7

## 2. 有声音但无画面或黑屏

检查 `m-video` 外层是否有明确且非零的高度。先用固定宽高验证，再恢复响应式布局。

```css
.video-wrap {
  width: 300px;
  height: 200px;
}
```

## 3. 没有声音且无法播放

1. 确认插件版本为 `latest` 或服务方当前最新版。
2. 查看微信开发者工具控制台。
3. 有报错：优先按报错处理，例如视频域名未加入白名单。
4. 无报错：继续检查域名、URL 字符、最小页面和官方 DEMO。

## 4. 真机非调试模式失败

所有视频 URL 涉及的域名都必须加入微信小程序服务器域名白名单。开发者工具或手机调试模式可能不拦截域名，因此“调试能播、真机非调试不能播”通常首先检查白名单。

## 5. URL 含中文或非英文字符

在传入组件前处理：

```js
const encodedVideoUrl = encodeURI(videoUrl)
```

不要对已经完整编码的 URL 反复编码。若业务传入的是 URL 片段或查询参数，应按现有 URL 构造逻辑分别编码，避免破坏签名参数。

## 6. 使用服务方测试视频隔离问题

测试地址：

```text
https://sucaicdn.xiaoaikeji.net/images/demo.mp4
```

必须先把 `sucaicdn.xiaoaikeji.net` 加入小程序白名单。若此地址能播放而业务地址不能，重点检查业务视频编码、响应头、域名和 URL 生成逻辑。

## 7. 建立最小复现页

新建空白页面，只保留：

- 插件组件注册；
- 一个有固定高度的外层容器；
- 一个 `m-video`；
- 正确 token；
- 服务方测试视频。

最小页能播而业务页不能播，逐项恢复业务属性、事件和布局，定位造成失败的代码。最小页仍失败，则下载对应技术栈的官网 DEMO，替换客户小程序 APPID 和 token 后对比运行。

## 8. 与原生 video 对照

服务方说明插件会把原生 `video` 的错误信息透传到前端。用同一 URL 对比原生 `video` 与 `m-video`：

- 两者都失败：优先检查视频文件、URL、域名、编码和微信原生组件限制。
- 仅 `m-video` 失败：检查插件声明、token、组件注册和插件版本，再联系服务方。

## 格式和直播限制

服务方文档称支持多数常见格式，包括 MP4、MOV、M4V、3GP、AVI、M3U8、WebM，但不同手机端最终受微信原生 `video` 能力限制，必须真机验证。

- M3U8 直播流：服务方称支持。
- RTMP 直播推流：服务方称不支持；可考虑在小程序中提供入口跳转视频号直播。

## 内容责任

服务方不会代为审核开发者的视频；内容安全和合规责任仍由小程序开发者承担。播放器资质能力不等于内容审核或版权授权。
